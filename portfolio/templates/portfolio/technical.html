RayJolt Pool

A full 8-ball billiards game built from scratch in C++ without a commercial engine—combining Raylib, Jolt Physics, EnTT (ECS), ENet (UDP), and Dear ImGui, compiled for Desktop and WebAssembly.

Game Architecture

Systems communicate exclusively through the central entt::registry—keeping gameplay rules, physics, rendering, audio, and LAN networking cleanly decoupled.

1. Tying Raylib & Jolt Physics Together

Instead of relying on a monolithic engine, PhysicsSetup and RenderSetup bridge Jolt's rigid-body simulation with Raylib's 3D rendering pipeline. Each ball uses EMotionQuality::LinearCast for continuous collision detection so high-power break shots never tunnel.

Pocket Illusion via Collision Layers

Cutting 6 circular holes into a static triangle mesh often creates snagging edges. Instead, I separated the table into STATIC rails and a solid SLATE bed. When a ball enters a pocket SENSOR, its layer swaps to SLATEBALLS, disabling collisions with the slate so it drops naturally into the pocket.

Solving Physics Edge Cases

Waking a cue ball touching an opponent ball normally fires OnContactAdded even when shooting away. By computing relative closing speed (dot(v_rel, n) > 0) in the contact listener, fouls only trigger when genuinely striking into a ball. Moving killplane-caught balls to SENSOR also prevents trailing balls from waking sleeping pocketed balls.

2. Loosely Coupled Gameplay with EnTT (ECS)

Every game object is composed of lightweight data components (TransformComponent, PhysicsComponent, RenderComponent, BallComponent, CueStickComponent), while systems communicate strictly through registry views and shared context resources (GameStateResource, TurnReport).

  • Thread-Safe Collision Bridging: Jolt's multi-threaded contact listener queues entity pairs under a mutex, which LogicSystem drains on the main thread before evaluating ball rest states.
  • Deterministic League Rules: RulesSystem evaluates pre-shot snapshots (handling break-shot 8-ball spotting, open-table group choices, scratch ball-in-hand placement, and Long-String non-overlapping ball respawns).
  • State-Driven Immediate UI: UISystem reads GameplayState and PendingDecision rather than tightly coupling UI callbacks into gameplay systems.

3. Server-Authoritative LAN Multiplayer (ENet)

Supports up to 4 players across 2 teams (any mix of local, remote LAN, and AI players) using a Host-authoritative UDP model built on ENet.

Responsive Client + Sanitized Authority

Clients run their aiming and power oscillation locally at 60 FPS so network jitter never stutters shot timing, streaming live aim previews to spectators. On release, the client sends a shot request that the host validates for turn ownership and clamps to legal power bounds before applying the Jolt impulse.

UDP Discovery & Fault Tolerance

Clients automatically discover LAN hosts via a non-blocking UDP broadcast beacon. If a client drops mid-match, the host can wait for a reconnect or seamlessly swap the slot to an AI bot; if a host disconnects, clients are given a retry or exit flow.

4. Ghost-Ball Geometry AI & Multi-Device Input

AISystem plays using the same rules and cue-stick state machine as human players—making it easy to drop AI bots into single-player, local co-op, or LAN lobbies.

  • Ghost-Ball Shot Solver: Computes the ideal impact point 2R behind each legal object ball along each pocket vector, scores cut-angle cosine and path clearance against blocking balls, and injects difficulty-tuned angular/power variance for Easy, Medium, and Hard bots.
  • Remappable Multi-Input: InputSystem unifies mouse, remappable keyboard bindings, dual-stick gamepads, and touchscreen gestures (drag-to-aim, pinch-to-zoom), with Jolt narrowphase raycasting for Ball-in-Hand surface placement and overlap validation.

5. Cross-Platform Builds, Shaders & Tooling

Leveraging my background in Systems & DevOps engineering, the project was architected to build cleanly across Linux, Windows, and WebAssembly (itch.io) from a single codebase.

  • WebAssembly & WebGL ES Port: Refactored the frame loop for Emscripten's requestAnimationFrame callback, switched Jolt to JobSystemSingleThreaded, and authored WebGL-compatible #version 100 GLSL lighting shaders alongside desktop shaders.
  • Resolution-Independent UI & Persistence: Built an automatic UI scaler (720p through 4K) and hooked into Dear ImGui's ImGuiSettingsHandler so graphics and audio preferences persist cleanly inside imgui.ini.
  • Voice-Pooled Audio with Fallbacks: SoundSystem scales ball-clack and rail-thud volume/pitch by Jolt collision velocity using Raylib LoadSoundAlias pools, with procedural waveform generation as an automatic fallback.
C++20 Core Frame Loop & Cross-Platform Entry
BilliardsGame.cpp

The entire game loop reads like a high-level pipeline: networking ticks every frame, authoritative simulation systems run on the host/local machine, and the same UpdateDrawFrame() drives both desktop and WebAssembly builds. 

void BilliardsGame::UpdateDrawFrame()
{
    if (IsWindowResized()) render->Resize();
    float dt = std::min(GetFrameTime(), 0.016f);

    auto& game = registry.ctx().get<GameStateResource>();
    const auto& binds = registry.ctx().get<InputBindingsResource>();

    // Poll ENet lobby, live aim streams, and authoritative table sync
    sysNetwork->Update(registry, network.get(), physics.get());

    if (!game.isGamePaused && game.currentGameState != GameplayState::MENU && game.disconnectedSlotIndex < 0)
    {
        // Only Host or Local/Single-Player runs authoritative rules & AI
        if (network->GetRole() != NetworkRole::CLIENT)
        {
            sysLogic->Update(registry, physics.get());
            sysRules->Update(registry, physics.get());
            sysAI->Update(registry, physics->GetSystem());
        }

        sysInput->Update(registry, physics->GetSystem(), render->GetCamera(), network->GetLocalPeerID());
        sysPhysics->Update(registry, physics.get(), dt);
    }

    sysSound->Update(registry);

    render->Begin();
        sysRender->Render(registry, physics->GetSystem());
        if (IsKeyDown(binds.keyDebugPhysics)) sysPhysics->DebugDraw(registry, physics->GetSystem());
    render->End();

    sysUI->Update(registry, physics.get(), network.get(), sysNetwork.get());
    render->FinalizeFrame();
}

void BilliardsGame::Run()
{
#if defined(__EMSCRIPTEN__)
    emscripten_set_main_loop_arg(
        [](void* arg) { static_cast<BilliardsGame*>(arg)->UpdateDrawFrame(); },
        this, 0, 1
    );
#else
    while (!WindowShouldClose()) UpdateDrawFrame();
#endif
}
EnTT ECS Decoupled Queries via Views & Context Resources
LogicSystem.cpp

Systems share state through registry.ctx() and operate on entities matching component views. Here, LogicSystem swaps pocketed balls onto the SLATEBALLS layer, updates TurnReport, and dispatches velocity-scaled audio events without holding a pointer to SoundSystem or RulesSystem. 

// Shared state accessed from registry.ctx() — no cross-system pointers needed
auto& game   = registry.ctx().get<GameStateResource>();
auto& report = registry.ctx().get<TurnReport>();
auto& audio  = registry.ctx().get<AudioStateResource>();

// 1. Ball vs. Pocket Sensor: drop ball through the slate & notify audio
if (registry.all_of<PocketComponent>(sensor) && !registry.all_of<PocketedTag>(ball))
{
    auto& ballComp = registry.get<BallComponent>(ball);
    auto& ballPhys = registry.get<PhysicsComponent>(ball);

    ballComp.sunkInPocket = registry.get<PocketComponent>(sensor).pocket;
    if (ballComp.group == BallGroup::CUE) report.cueBallSunk = true;
    else report.ballsPocketed.push_back(ball);

    // Swap collision layer so the ball falls through the solid slate bed
    bi.SetObjectLayer(ballPhys.bodyID, Layers::SLATEBALLS);
    bi.ActivateBody(ballPhys.bodyID);
    registry.emplace<PocketedTag>(ball);

    audio.PlaySFX(SoundEffectType::POCKET_DROP, 1.0f);
}

// 2. View query: advance state machine once all active balls come to rest
bool anyMoving = false;
auto view = registry.view<PhysicsComponent, BallComponent, TransformComponent>();
for (auto entity : view)
{
    if (bi.IsActive(view.get<PhysicsComponent>(entity).bodyID))
    {
        anyMoving = true;
        break;
    }
}
if (!anyMoving) game.currentGameState = GameplayState::EVALUATING;
ENet UDP Packed Binary Packets & Sanitized Host Authority
NetworkSystem.cpp

Compact, byte-packed UDP packets minimize bandwidth. Clients charge shots locally for smooth 60 FPS feel, while the host verifies turn ownership (isCurrentShooter) and sanitizes incoming values before applying impulses to the authoritative Jolt simulation. 

#pragma pack(push, 1)
struct PktShotRequest { uint8_t type = PKT_SHOT_REQUEST; float rotation; float power; };
struct PktLiveAim     { uint8_t type = PKT_LIVE_AIM; float cueRotation; float cuePower; bool isCharging; float bihX, bihZ; };
struct PktTableSync
{
    uint8_t type = PKT_TABLE_SYNC;
    GameplayState gameState;
    PendingDecision pendingDecision;
    uint8_t activePlayerIdx;
    bool isTableOpen, isBreakShot, restrictToKitchen;
    PocketLocation calledPocket;
    float cueRotation, cuePower, bihX, bihZ;
    BallGroup playerGroups[4];
    uint8_t sunkCount, sunkBalls[16];
    BallNetState balls[16];
};
#pragma pack(pop)

void NetworkSystem::ExecuteSanitizedServerShot(entt::registry& registry, PhysicsSetup* physSetup, float rotation, float rawPower)
{
    auto& game = registry.ctx().get<GameStateResource>();
    if (game.currentGameState != GameplayState::AIMING && game.currentGameState != GameplayState::SHOOTING) return;

    // Sanitize client inputs to prevent NaN injection or spoofed shot power
    if (!std::isfinite(rotation)) rotation = 0.0f;
    if (!std::isfinite(rawPower)) rawPower = 0.05f;
    float cleanPower = std::clamp(rawPower, 0.05f, 1.0f);

    // Apply validated impulse to the cue ball on the authoritative host
    Vector3 dir = { -std::cos(rotation), 0.0f, -std::sin(rotation) };
    JPH::Vec3 impulse(dir.x * cleanPower * 100.0f, 0.0f, dir.z * cleanPower * 100.0f);

    auto& bi = physSetup->GetSystem()->GetBodyInterface();
    bi.SetObjectLayer(cueBallBodyID, Layers::BALLS);
    bi.ActivateBody(cueBallBodyID);
    bi.AddImpulse(cueBallBodyID, impulse);

    game.currentGameState = GameplayState::RESOLVING;
}
